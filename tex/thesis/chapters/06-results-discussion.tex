\chapter{Results and Discussion}
\label{chap:evaluation}

This chapter evaluates predictive performance, calibration, feature attribution,
errors, and robustness to repository recurrence and the label definition.
Aggregate performance is compared with the active-at-\(t\) subset to separate
activity persistence from early-warning skill.

\section{Predictive Performance}
\label{sec:results-performance}

histogram calibration. Differences therefore reflect model family. The combined
quality score summarizes ROC-AUC and Brier for comparison; it is not standalone
evidence. Appendix~\ref{sec:method-metric-definitions} defines the metrics.

The ordering is stable across regimes. The full-history XGBoost model has
ROC-AUC \(0.958\) and Brier \(0.078\), followed by the neural network
(\(0.956\) / \(0.081\)) and Logistic Regression
(\(0.949\) / \(0.088\)). The neural network has the lowest calibration error but
does not improve ranking or Brier over XGBoost. It also costs more to train and
is less interpretable, consistent with evidence favoring trees on moderate
tabular data \cite{grinsztajn2022trees}. Logistic Regression is retained for
coefficient attribution, XGBoost for runtime scoring, and the neural network as
a tested alternative.

Cold-start is only marginally weaker for the non-linear models.
\texttt{xgboost\sdash cold\sdash start} reaches \(0.953\) against \(0.958\)
with the smaller feature set. Logistic Regression falls from \(0.949\) to
\(0.932\). The cold-start vector retains
\texttt{last\_push\_age\_days}, a strong substitute for reconstructed commit
history on this mixed test set, although it lacks the commit-window features
that dominate full-history gain (Section~\ref{sec:results-attribution}). The
XGBoost gap is \(0.005\) in aggregate but \(0.030\) after removing the
already-quiet majority
(Section~\ref{sec:results-history-ablation}).

\subsection{Comparison Against Non-Learned Baselines}
\label{sec:results-baselines}

Since the label is activity-derived, single-signal rules show how much ranking
skill is available without learning
(Section~\ref{sec:method-model-training}). The baselines use days since the last
human commit and negated annual commit volume.

On the aggregate rows, recency reaches ROC-AUC \(0.957\) and F1 \(0.918\);
XGBoost reaches \(0.958\) and \(0.916\). This is not a like-for-like comparison.
\texttt{days\_since\_last\_commit} is undefined for \(444\) rows without prior
observed events (Section~\ref{sec:method-undefined-features}), so recency covers
\(4{,}556\) rows and XGBoost all \(5{,}000\).

Re-scored on the \(4{,}556\) shared rows, XGBoost reaches \(0.974\) against
\(0.957\), a margin of \(0.018\). Increments use unrounded metrics before
rounding and may differ from subtractions of displayed values. F1 was \emph{not}
recomputed on the shared rows and is not compared; no claim rests on the F1
column of Table~\ref{tab:model-comparison}. Commit volume is weaker on the full
test set (\(0.897\)) but is the stronger trivial rule on recency-defined rows
(Section~\ref{sec:results-history-ablation}).

At the inactive base rate of \(0.661\), recency already supplies most
aggregate ranking skill. The sixty-feature model adds a modest increment
\emph{on a test set where most repositories are
already quiet}. On the
\(1{,}794\) repositories still active at \(t\), XGBoost reaches \(0.905\)
against \(0.844\) for the best trivial rule. This margin is \(0.061\), compared
with \(0.016\) on the recency-defined rows
(Section~\ref{sec:method-evaluation-strategy}).

\subsection{Early Warning: Removing the Already-Inactive Repositories}
\label{sec:results-history-ablation}

The active-at-\(t\) subset removes repositories already silent at the
observation date. Its inactive rate is \(0.225\), compared with \(0.661\) for
the full test set.

Comparing the two XGBoost regimes isolates the 43 reconstructed historical
features (Section~\ref{sec:method-prediction-regimes}).
Table~\ref{tab:history-ablation} scores every arm on identical recency-defined
and active-at-\(t\) rows. Rows without recency are dropped from \emph{all} arms. The
trivial column selects commit volume, the stronger rule in both sets:
\(0.958\) against \(0.957\) for recency-defined rows and \(0.844\) against
\(0.792\) for active-at-\(t\). Section~\ref{sec:results-baselines} instead uses
recency specifically, so its margin has a different comparator.

On recency-defined rows, history adds \(0.005\) ROC-AUC and the 17 snapshot
features add \(0.011\) over the best single signal. On active-at-\(t\), the gains
are \(0.030\) and \(0.031\); the historical gain is six times its aggregate
value. The ordering from one to 17 to 60 features is nearly flat in aggregate and
strictly monotone in the early-warning subset.

The learned model exceeds the best trivial rule by \(0.016\) on recency-defined
rows and \(0.061\) on active-at-\(t\). The full test set is dominated by
repositories already quiet at \(t\), so aggregate ROC-AUC largely measures
activity persistence. Among repositories still active at \(t\), XGBoost reaches
\(0.905\) against \(0.844\); the repository-clustered bootstrap also supports
this margin (Section~\ref{sec:validity-conclusion}). The learned contribution is
therefore concentrated
\emph{among repositories that are active at the observation time}, while the
aggregate advantage over a trivial rule remains
small.\kiref{Claude Opus 5/4}

\subsection{Precision-Recall Evaluation of the Early-Warning Subset}
\label{sec:results-precision-recall}

ROC-AUC measures pairwise ranking across both classes and is insensitive to class
prevalence. Average precision summarizes the precision-recall curve for the
positive class and uses the positive rate as its no-skill reference
(Appendix~\ref{sec:method-metric-definitions}). It provides an additional view
for active-at-\(t\), whose inactive rate is \(0.225\)
\cite{saito2015precision}. Table~\ref{tab:average-precision} reports it for the
same held-out predictions and row sets as Table~\ref{tab:history-ablation}, with
percentile intervals from \(2{,}000\) bootstrap resamples.

The split finding of Section~\ref{sec:results-baselines} is sharper under this
metric than under ROC-AUC. On recency-defined rows, all three average-precision
scores are high, and the model's margin over the better trivial rule --- recency
under this metric, not commit volume as in Table~\ref{tab:history-ablation} --- is
\(0.007\) \([0.005, 0.009]\). On active-at-\(t\), the margin is \(0.127\)
\([0.096, 0.160]\) against commit volume, the better rule there, and \(0.213\)
\([0.159, 0.264]\) against recency. All intervals exclude zero. Relative to the
no-skill line of \(0.225\), the model reaches \(3.2\) times the random rate and
the better trivial rule \(2.7\) times.

The corresponding ROC-AUC margin is \(0.061\)
(Table~\ref{tab:history-ablation}). Average precision supports the same conclusion
and shows a larger separation between the model and the trivial rules. Because
the principal comparison is summarized by the areas and bootstrap intervals, no
precision-recall curve is included. The resulting loss of operating-point detail
is discussed in Section~\ref{sec:validity-conclusion}. The analysis is reproduced
by
\texttt{scripts\sslash ml\sslash precision\su recall\su eval\sdot py}, which
reruns the reported configuration and aborts if the re-scored predictions do not
reproduce that run's held-out ROC-AUC
(Appendix~\ref{appendix:code-availability}). The rerun reproduces the staged
run's aggregate ROC-AUC of \(0.957852\), so
Tables~\ref{tab:history-ablation} and~\ref{tab:average-precision} describe the
same fitted model.\kiref{Claude Opus 5/12}

\section{Calibration and Threshold Selection}
\label{sec:results-calibration}

Calibration is evaluated because the score is presented as a probability. The
histogram calibrator uses validation data, never test data. For
\texttt{xgboost\sdash full\sdash history}, Brier is \(0.078\), log loss
\(0.246\), and ECE \(0.035\). At the selected threshold of \(0.51\), precision
is \(0.90\) and recall \(0.93\). The neural network has the lowest full-history
ECE (\(0.028\)); Logistic Regression has the highest (\(0.047\)). Calibration
and discrimination therefore order the models differently.

Empirical inactivity increases monotonically across the ten calibration bins,
from \(0.032\) in the lowest band to \(0.988\) in the highest. The two extreme
bands contain \(65.9\%\) of validation predictions, leaving less support for
mid-range probabilities. The demonstrator's per-prediction evidence measure
reflects this bin support (Chapter~\ref{chap:demonstrator}). Calibration is also
conditional on sampled prevalence; live population probabilities require
recalibration (Section~\ref{sec:method-limitations}).

\section{Feature Importance and Error Analysis}
\label{sec:results-features}

This section compares standardized Logistic Regression coefficients with
XGBoost gain, then examines repository recurrence, subgroup performance, and
errors.

\subsection{Feature Attribution}
\label{sec:results-attribution}

Logistic Regression provides transparent attribution for
\texttt{xgboost\sdash full\sdash history}'s comparison model
(Section~\ref{sec:results-performance}). Standardized inputs make coefficient
magnitudes comparable, and signs indicate the \emph{direction} of association
with inactivity.
Figure~\ref{fig:attribution} shows the leading coefficients.\kiref{Claude Opus 5/5}

Sustained development is the strongest inactivity-lowering signal, followed by
recent maintainer integration and any issue activity. The two staleness measures
are the strongest inactivity-raising signals
(Appendix~\ref{appendix:feature-reference}).

Two coefficients have counter-intuitive signs. Larger issue backlogs associate
with \emph{lower} inactivity, while more stars associate with \emph{higher}
inactivity. These
associations may be confounded: a backlog implies users who file issues, and
stars may proxy unobserved project characteristics because repository age is
unavailable (Section~\ref{sec:method-offline-metadata}). The coefficients
describe association, not causation; XGBoost provides ranking performance.

Before the encoding correction in
Section~\ref{sec:method-undefined-features}, zero response latency marked projects
with no issues or pull requests. Responsiveness medians then appeared among the
strongest signals with a misleading meaning. After correction, they leave the
leading coefficients, and \texttt{has\_issue\_activity\_365d} and
\texttt{has\_pr\_activity\_365d} carry the absence of activity explicitly.

XGBoost gain is normalized over the \(42\) of \(60\) features used in at least
one split. \texttt{commits\_365d} (\(0.42\)) and
\texttt{commits\_90d} (\(0.20\)) provide over three-fifths of total gain.
\texttt{active\_commit\_months\_365d} (\(0.08\)) and
\texttt{has\_recent\_pr\_merge\_flag} (\(0.07\)) follow;
\texttt{last\_push\_age\_days}, \texttt{opened\_prs\_90d},
\texttt{days\_since\_last\_commit}, and \texttt{merged\_prs\_90d} form the next
tier.

Both models emphasize recent sustained development. The linear model emphasizes
active commit months, while XGBoost concentrates gain on commit-volume windows.
Cold-start omits these windows, but \texttt{last\_push\_age\_days} substitutes
for them on the already-quiet majority. The substitution is weaker on
active-at-\(t\) (Section~\ref{sec:results-history-ablation}).

\subsection{Robustness to Repository Recurrence}
\label{sec:results-robustness}

With every repository confined to one partition, the
\texttt{xgboost\sdash full\sdash history} model is retrained,
recalibrated, and rethresholded on that partitioning
(Appendix~\ref{sec:impl-grouped-split}). ROC-AUC falls from \(0.958\) to
\(0.950\) and Brier rises from \(0.078\) to \(0.079\). The small change bounds
optimism from repository recurrence and indicates discrimination on repositories
held out from the same foundation frame, not transfer to open-source
repositories in general (Section~\ref{sec:method-data-sources}). This check is
necessary because ten equal quarterly cohorts make the chronological test set the
final date, while every test repository also appears earlier in training.
Section~\ref{sec:validity-internal} treats this as an internal-validity threat.

\subsection{Slice Evaluation}
\label{sec:results-slices}

The \texttt{xgboost\sdash full\sdash history} predictions are re-scored by
subgroup to identify variation hidden by the aggregate.
Appendix~\ref{appendix:eval-tables}
(Table~\ref{tab:slice-metrics}) gives the full results.

On active-at-\(t\) (\(n=1{,}794\), inactive rate \(0.225\)), XGBoost reaches
\(0.905\) ROC-AUC with a \(95\%\) repository-clustered bootstrap CI of
\([0.889, 0.921]\). Each snapshot in this test subset belongs to a distinct
repository, so the interval equals an ordinary row bootstrap. Recency reaches
\(0.792\) and commit volume \(0.844\). The \(0.061\) margin over the best rule
has a \(95\%\) CI of \([0.046, 0.078]\), excluding zero, compared with \(0.016\)
on recency-defined rows (Section~\ref{sec:results-baselines}). At the selected
operating point, recall is \(0.49\) and precision \(0.74\). The model therefore
ranks early decline but flags fewer than half of the repositories that later fall
quiet.

Low-popularity repositories reach \(0.846\), compared with \(0.972\) and
\(0.964\) for high and medium popularity (Table~\ref{tab:slice-metrics}). They
require more caution, although ``low'' is relative to a seed requiring at least
100 stars. Per-prediction evidence support should surface this weakness.
Repositories with reconstructable history reach \(0.921\), compared with
\(0.929\) for cold-start-like rows. The latter subgroup has a much higher
inactive rate (\(0.924\) against \(0.350\)), so this does not show that history
is unhelpful. It only confirms that aggregate regime performance is close
(Section~\ref{sec:results-performance}).

\subsection{Error Analysis}
\label{sec:results-error-analysis}

Two weaknesses remain. Low-visibility repositories provide sparse public
signals. Evidence support flags this condition, but its relationship with
prediction error has not been validated separately. On active-at-\(t\), the
F1-selected threshold also detects only about half of later inactivity. The score
should therefore rank manual review, not gate decisions; it provides \emph{no}
automatic acceptance rule.

\section{Robustness to the Label Definition}
\label{sec:results-label-sensitivity}

The evaluation repeats the heuristic two-of-four rule with permissive one-of-four
and strict three-of-four variants (Section~\ref{sec:method-definitions}). The
harness re-labels all \(50{,}000\) snapshots, retrains full-history XGBoost, and
exactly reproduces the primary run. The inactive rate ranges from \(0.581\) to
\(0.746\), while full-test ROC-AUC remains between \(0.958\) and \(0.961\).

On identical recency-defined rows, the margin over the stronger trivial rule is
\(0.010\), \(0.016\), and \(0.023\) as the rule tightens
(Section~\ref{sec:results-baselines};
Appendix~\ref{appendix:label-sensitivity}). The learned margin therefore widens
with the stricter rule, and the threshold choice does not produce the central
ranking result. A systematic sweep over each cut-off remains future
work.\kiref{Claude Opus 5/9}

The human-actor filter applies to commit and contributor features and to the
label. Disabling it changes ROC-AUC by only
\(0.0006\)--\(0.0011\) across model families
(Section~\ref{sec:method-feature-engineering}). It changes the label in one
direction: \(357\) of \(50{,}000\) snapshots switch from inactive to active,
with none switching back. Bots can make a dormant project appear maintained but
cannot make an active one appear inactive. The filter is therefore justified by
construct validity, not predictive accuracy
(Appendix~\ref{appendix:bot-ablation}).\kiref{Claude Opus 5/4}
