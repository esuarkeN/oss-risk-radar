\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

Modern software depends on open-source components, but downstream projects face
maintenance and security exposure when an upstream repository becomes inactive. This
thesis investigates whether public repository health and maintenance indicators
predict inactivity within twelve months and support dependency triage. Following
a Design Science Research-oriented approach, it develops OSS Risk Radar. The
artifact reconstructs a leakage-controlled historical dataset from GH Archive
and public package metadata, computes observation-time activity and maintenance
features, and trains calibrated inactivity-risk models.

The foundation dataset contains 5{,}000 repositories and 50{,}000 quarterly
snapshots. Full-history XGBoost reaches held-out ROC-AUC \(0.958\), the
probability that an inactive repository ranks above an active one, with Brier
score \(0.078\). A repository-disjoint split reaches \(0.950\). On rows where
commit recency is defined, that trivial rule reaches \(0.957\), compared with
\(0.974\) for XGBoost on the same rows. Among repositories still active at the
observation date, XGBoost reaches \(0.905\) against \(0.844\) for the best
trivial rule. Most aggregate discrimination is therefore available from recency,
while the learned model adds more for early decline.

Security-practice signals remain separate triage context and do not enter the
inactivity model. A practical demonstrator applies the staged models per
repository to a real project's dependencies and produces a ranked view with
evidence support. It demonstrates technical integration, not improved analyst
decisions. Repository inactivity remains an operational proxy for elevated
maintenance risk, not proof of abandonment or software insecurity.
